# 内容规则（写什么、怎么措辞）

## 1 一页的骨架：总 — 分 — 总

```
标题（做什么 + 得到什么）
导语（一句话核心事实，读者只看这句也知道本页价值）
主体（01 / 02 / 03 三块以内，或表格 / 流程 / 图）
总结句（结论 + 边界，必须有）
```

四者缺一，页面就散。`build_deck.py --check` 会检查导语与总结句是否缺失。

## 2 标题公式

标题不是标签，是**结论**。必须包含动作或对象，以及目的或结果。

**公式 A（学习 / 方法类）**：`序号 + 动作/对象 + 核心目的或结果`

| ✅ 好 | ❌ 差 |
|---|---|
| Python 第 3 题：解析 GFF3 并统计 CDS | Python 练习 |
| 代码思路：把生物学规则翻译成 Python | 代码讲解 |
| 结果核对：三类检查确认解析正确 | 结果展示 |
| Linux 命令与结果质量控制 | Linux 学习 |

**公式 B（文献 / 结论类）**：`序号 + 结论X：核心发现`

| ✅ 好 | ❌ 差 |
|---|---|
| 结论 1：细胞类型蓝图保守，差异集中于少数类型 | 结论一 |
| 实验数据：成年中央凹图谱包含 68 个类型 | 实验结果 |
| 创新点 2：从图谱推进到可检验的机制假说 | 创新点 |

字数控制：18–28 字（中文），单行为宜。超过 30 字就拆页。

## 3 导语句

位置：标题下方浅蓝带。一句话，≤ 60 字，写**本页最重要的那个事实**，不是背景铺垫。

- ✅「Bulk 给出组织平均值；scRNA-seq 保留每个细胞的表达身份，因此能解析异质性。」
- ✅「四组 scRNA-seq 构成主轴，snRNA-seq、FISH 与 scATAC-seq 提供补充证据。」
- ❌「下面我们来学习单细胞测序的相关知识。」

## 4 主体分块

- 一律用 `01 / 02 / 03`（或「首先 / 其次 / 最后」），**最多 3 块**。
- 每块 = 小标题（4–8 字名词短语）+ 正文（1–3 句，每句 ≤ 35 字）。
- 超过 3 块 → 拆成两页，或用表格。
- 并列/对比 → `table`；时间/步骤 → `flow`；两张并列长文 → `compare`；图为主 → `figure`。

## 5 总结句（签名项）

位置：页面底部，前面有 0.19 宽竖条。三类开头，必选其一：

| 类型 | 开头 | 颜色 | 示例 |
|---|---|---|---|
| 结论 | `结论：` / `因此，` | 深蓝 | `结论：类型身份在出生时已建立，区域差异随后叠加。` |
| 边界 | `结论边界：` | 深蓝 | `结论边界：保守性来自多 marker 的一致性，不能由单个基因一票决定。` |
| 注意 | `注意：` / `局限：` | 橙 | `注意：通用 GFF3 可能同时含 gene、mRNA 和多个转录本，脚本应按实际层级解析。` |

`note_kind` 取 `conclusion`（默认，深蓝）或 `warning`（橙）。**每 2–3 页至少有一页是 `warning`**，
这是汇报可信度的来源。

## 6 图表绑定

- 引用文献图必须写编号：`论文 Fig.1B：中央凹结构与侏儒通路示意`（图注 11.25pt 灰）。
- 图旁或图下必须有一句「这张图说明什么」，不能只放图。
- 讲图先讲坐标轴与图例，再讲结论（见 `speech.md` 的 Read 段）。
- 自己的分析结果（UMAP、热图）图注写「本分析：…」，与文献图区分。

## 7 措辞替换表

| 别写 | 改写 |
|---|---|
| 我觉得 / 我认为 | 数据显示 / 这表明 |
| 可能 / 或许 / 大概 | 说明 / 提示 / 在…条件下成立 |
| 效果很好 | 一致性达到 X% / 三类证据互相支持 |
| 做了很多分析 | 完成 QC → 聚类 → 注释三步 |
| 这个方法很厉害 | 该方法把 X 换成 Y，因此能回答 Z |
| 结果没问题 | 数量、字符、长度分布三项核对一致 |

## 8 中英混排

- 专有名词保留英文（scRNA-seq、UMAP、GFF3、CDS、orthotype），首次出现可加中文注释。
- 数字与英文之间加空格：`68 个类型`、`17,064 条 mRNA`。
- 单位统一：`cm / μm / nt / aa`，不写「厘米」。

## 9 自检清单（交付前逐条过）

| 检查项 | 谁查 |
|---|---|
| 标题能独立读懂，不是「XX介绍」，且含冒号 | 脚本（空泛标题直接拦，缺冒号给提醒） |
| 每页有导语，导语不是背景废话 | 脚本查有无，人查好坏 |
| 分块 ≤ 3，每块正文 ≤ 3 句 | 脚本 |
| 每页有总结句，且带条件或边界 | 脚本查边界词，人查是否说通 |
| 对比用了表格，流程用了 flow | 人查 |
| 图有 Fig. 编号图注 + 一句解读 | 脚本查编号格式 |
| 没有「我觉得 / 或许 / 大概 / 似乎」 | 脚本（「可能」只提醒，要求补条件） |
| 单句 ≤ 46 字 | 脚本提醒 |
| 全文没有一页超过 2 种强调色 | 人查 |

## 10 脚本会拦下的 6 类问题

`build_deck.py` 里的 `check()` 就是按本文件写的，跑 `--check` 会逐条报页码：

1. **空泛标题**：`方法介绍 / 结果展示 / 研究背景 / 讨论 / 小结` 直接判错。
2. **缺总结句**：`points / cards / table / flow / compare / stats / figure` 七种版式都必须有 `note`。
3. **总结句没有边界**：`note` 里必须出现「边界 / 局限 / 注意 / 适用条件 / 不代表 / 不等于 / 只能 / 仅在 / 不是 / 取决于 / 不能 / 前提是」之一。
4. **图注无编号**：`caption` 必须匹配 `Fig.1B` / `图 3` / `Figure 3` 之一。
5. **模糊词**：正文、标题、表格、讲稿里出现「我觉得 / 我认为 / 或许 / 也许 / 大概 / 似乎 / 估计是」判错；「可能 / 应该是 / 一般来说」只提醒，要求改写成「在…条件下」。
6. **句子太长**：单句超过 46 字提醒断句。
